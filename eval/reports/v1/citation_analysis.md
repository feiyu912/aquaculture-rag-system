# 50 条答案的引用一致性

> 运行：`eval/runs/answer_quality_50/`（details.jsonl、summary.json、citation_analysis.json）
> 数据：`eval/retrieval_eval_100_v1.jsonl` 前 50 题，模式 hybrid_rerank，max_sources=15。
> 生成：deepseek-v4.1-flash（关闭 thinking），temperature 0.2。

## 结果

| 指标 | 值 |
|---|---|
| 出答数 | 50/50 |
| 引用覆盖率均值（有引用的句子占比） | 0.691 |
| 非法引用编号 | 0 例 |
| 带引用句子 | 429 |
| 引用后句子与所引父块 4-gram 重合 ≥0.35 | 384（**89.5%**） |
| 无引用的“事实型”句子 | 150 |
| 平均答案长度 | 622 字 |
| 平均检索 / 生成耗时 | 7.6 s / 7.6 s |

## 怎么判的

对每个带 `[S1]` 标记的句子，取所引父块原文，计算句子字符 4-gram 在原文中的覆盖率；
≥0.35 记为“支持”。这是**词面证据**，不是蕴含判断：改写、概括、跨块综合都会被判低，
所以 89.5% 是下界，不是准确率。

## 需要人工复核的两类

1. **元话语被当成事实句**（E002）：答案在解释“现有资料分别是 2026年8月、2026年6月……”，
   这些句子带引用但引用的不是支撑事实，而是来源清单。应在生成约束里禁止“资料罗列”段落，
   或在引用校验里排除元话语。
2. **具体数值与所引块不重合**（E004）：“泥蚶滤食率显著降低 [S2]”“摄食成功率由 67% 降至 12% [S2]”
   在父块中找不到对应片段，可能是跨块拼接或模型改写。这 45 句必须逐条对照原文；若确属
   跨块，应把引用从父块细化到子块（当前引用粒度只到父块）。

## 另外两个观察

- 50 条答案全部出答，没有触发拒答；与拒答测试的 0.60 合起来看，门禁偏松。
- `gold_source_cited` / `gold_in_evidence` 记为 0，原因是评测脚本拿 `gold_chunk_ids`（子块）
  与父块 id 比较，属于脚本口径问题，不是模型没引到来源；本报告不使用这两个字段。

## 结论

结构层面（引用编号合法、覆盖率）已经可用；语义层面只能给到“89.5% 词面支持”的下界。
论文里应写成“引用覆盖 69.1%，其中 89.5% 的引用句在词面上可由所引父块支持，剩余需人工判读”，
不能写成“引用准确率 89.5%”。
