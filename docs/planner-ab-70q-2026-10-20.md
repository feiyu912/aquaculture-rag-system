# 规则 IR vs LLM IR：planner 探针与 70 题对照（2026-10-20）

> 链路固定：`BGE-M3 dense + BM25 sparse -> RRF -> BGE-reranker-v2-m3 -> gate -> LLM`。
> 两组唯一差异是 `QueryIR` 由规则还是由 LLM planner 生成；reranker、gate 阈值、
> `top_k=10`、source-aware 默认值完全相同。

| P05 | 1.00 | 1.00 | ✗ | ✓ | 1/1 | 3 |
| P06 | 0.80 | 0.80 | ✗ | ✗ | 1/1 | 1 |

汇总：字段准确率 **0.9133 / 0.9133**；子问题合格率 **0.0 / 0.8**；硬过滤

## 2. 70 题检索对照

70 题、`hybrid_rerank`、`top_k=10`、当前默认（source-aware 开、targeted 开、
`ENABLE_LLM_PLANNER` 按组切换）。指标按全部 70 题和“实际作答的 65 题”分别统计。

| 指标 | 规则 IR（70） | LLM IR（70） | 规则 IR（65 作答） | LLM IR（65 作答） |
|---|---|---|---|---|
| Recall@5 | **0.8452** | 0.8238 | **0.9103** | 0.8872 |
| Recall@10 | **0.8810** | 0.8643 | **0.9487** | 0.9308 |
| nDCG@5 | **0.8500** | 0.8313 | **0.9154** | 0.8952 |
| nDCG@10 | **0.8810** | 0.8663 | **0.9488** | 0.9329 |
| MRR@10 | **0.8053** | 0.7672 | **0.8672** | 0.8262 |

- 两组都拒答 5 题：`R017`、`R036`（法规时效未验证）、`R063`、`R065`（域外）、
  `R064`（法规时效）；拒答率一致，说明 LLM 没有把该拒的题“救”成错答。
- LLM 使用 48/70（20 题被 `simple_rule_ir` 跳过，2 题 API 失败回退规则）。
- 逐题看：LLM **更差 2 题**（R024 1.0→0.5，R066 1.0→0.0），**更好 0 题**。
- targeted loop 在两组各触发 2 次（R063/R065），`sufficient_after=false`，
  仍然拒答——没有靠补检索放宽 gate。

### 为什么 LLM 反而更差

以 R066（“DB32/T 5292—2025 生态育苗的水温和 pH 适宜范围”）为例，LLM 拆成 3 个
task 并加“中华绒螯蟹”重写：

```text
task1 中华绒螯蟹 DB32/T 5292—2025 中生态育苗的水温适宜范围是多少？
task2 中华绒螯蟹 DB32/T 5292—2025 中生态育苗的pH适宜范围是多少？
task3 DB32/T 5292—2025 的适用范围是否包括中华绒螯蟹生态育苗？
rewritten: DB32/T 5292—2025 生态育苗 水温 pH 适宜范围 中华绒螯蟹
```

多 task 变体一起进 RRF，把“该标准 5.x 生态育苗”段落挤到第 5 名之外；规则 IR 的
单查询反而把 gold 排在第 1。结论：**多 task 融合会稀释单标准、单段落的精确匹配**，
在当前 reranker 输入长度（512 token）下尤其明显。

## 3. 下游回答质量（8 题 × 规则/LLM）

8 题（R001 简单事实、R014 投喂量、R017 法规时效拒答、R026 多指标、R051 六项水质、
R061 跨标准、R062 跨物种、R066 单标准单段落），真实 LLM 生成，`max_sources=5`。
指标是确定性可测的：是否作答、引用覆盖率（有引用的事实句比例）、引用是否越界、
是否引到 gold 文档。**不是事实正确率**（那需要盲评）。

| 指标 | 规则 IR | LLM IR |
|---|---|---|
| 作答 / 拒答 | 7 / 1 | 7 / 1 |
| 引用覆盖率均值 | **0.634** | 0.574 |
| 越界引用题数 | 0 | 0 |
| 引到 gold 文档 | 7/7 | 7/7 |
| 回答平均字数 | 375 | 459 |
| 生成耗时均值 | 8.8 s | 7.7 s |

逐题看，LLM 在 R001（0.50→0.60）和 R061（0.57→0.67）覆盖更好，但在 R051
（0.80→0.56）和 R066（1.00→0.57）更差；拒答与 gold 引用两组一致。结论与检索层一致：
LLM planner 没有带来稳定收益，R066 的退化与检索层多 task 稀释同源。

> 注意：`citation_coverage` 只检查“事实句是否带 `[Sx]`、编号是否越界”，不判断引用
> 是否真的支持该句；`gold_source_cited` 只看 gold 文档是否被引，二者都不能单独当
> “回答正确”的证据。

## 5. 结论与边界

1. **当前题库上规则 IR 优于 LLM IR**（R@5 0.8452 vs 0.8238，MRR 0.8053 vs 0.7672），
   与 `ENABLE_LLM_PLANNER=false` 的默认值一致，本轮不改成默认开。
2. LLM 的唯一稳定收益是子问题拆分（0.0→0.8）；它没有修正字段错误，反而在 R066 这类
   “单标准单段落”问题上因多 task 稀释而丢 gold。
3. 延迟：顺序执行时规则检索平均 2.48 s/题；LLM 规划平均 22.5 s/题（API），并发只影响
   吞吐，不改变单题质量。上表的 `retrieval_ms` 是并发 6 下的墙钟，不能当单题延迟引用。
4. 语料规模小（70 题、89 篇文档），结论是“本库上不开”，不是“LLM planner 无用”；
   多跳/跨文档问题需要 LLM 拆分时，应配合 task 级过滤或降低融合权重，这轮未做。
