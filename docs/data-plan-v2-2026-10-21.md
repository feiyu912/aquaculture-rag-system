## 2. 成本模型（按 5,000 份估算）

假设：PDF 平均 25 页、HTML 平均 8 屏；平均 60 个子块/份 → **30 万子块**。

| 项目 | 估算 | 说明 |
|---|---|---|
| 磁盘（原始文件） | 40–80 GB | PDF 平均 8–15 MB |
| Postgres（正文+块） | 3–6 GB | 30 万块 × ~600 字 |
| Qdrant 向量 | 4–6 GB | 30 万 × 1024 dim × 4B + payload + 索引 |
| 快照/备份 | 10–20 GB | 200/500/1000/2000 冻结快照 |
| Embedding 计算 | 本地 2–4 h（MPS）/ 12–20 h（CPU） | 30 万块 × 512 token ≈ 1.5 亿 token，**无 API 费用** |
| 解析 | 6–12 h | 含 OCR 失败重试 |
| DeepSeek API | ¥0（采集阶段不调用） | 只在评测/生成时用 |
| 人工/自动审核 | 自动卡片 ~2 s/篇 | LLM 只做摘要，不判定专业结论 |

**触发上报的阈值**：单源下载 > 5 GB、单日 embedding > 4 h、API 费用 > ¥50，立即停下报告。

## 3. 流水线设计（断点可恢复）

状态机（每条资料一行，独立于 `kb_documents`）：

```
discovered → downloaded → parsed → tech_reviewed → domain_reviewed → published
                    ↘ failed(reason)        ↘ rejected(reason)
```

新增 `data_items` 表（`url` 唯一、`sha256` 唯一、`simhash`、`state`、`attempts`、`last_error`、`source_id`、`license`、`fetched_at`）。要点：

1. **发现与下载分离**：先用 sitemap/OAI/列表页产出 `discovered`（只存 URL+标题），不下载。
2. **增量**：按 `url` 与 `sha256` 去重；`If-Modified-Since` + 快照 hash 判更新；已有 embedding 不重算。
3. **PDF/HTML 同源去重**：`simhash` 近重复（汉明距离 ≤3）+ 标题归一化；同内容保留 HTML 快照并关联 PDF。
4. **分批提交**：每 100 条提交一次 `state`，`--resume` 从断点继续。
5. **限速**：默认 2 s/域名，robots 严格判定；失败退避 3 次。
6. **审计**：每次运行写 `data_runs`（已实现）+ 源级统计。

## 5. QA 数据集（不计入 5,000）

5 个数据集先做**可获取性验证**再谈全量：下载入口、许可、字段、实际样本数、彼此是否重打包。分层：`verified_faq / pending_faq / rejected_faq / eval_candidate / retrieval_hint`。**LLM 不得批量标 verified**；`eval_candidate` 与可检索 FAQ 做簇级隔离。

## 6. 需要你决策（阻塞项）

1. **网络可达性**：FAO/SRAC/AquaDocs 当前不可达。是否允许我换用镜像/开放副本，还是等校园网环境？
2. **标准全文版权**：地方标准 PDF 是否可在论文系统中存储全文？只存元数据+链接也可。
3. **磁盘预算**：预计 60–100 GB，是否可接受。
4. **时间预算**：到 2,000 份约需 3–5 个工作日（含解析与审核），到 5,000 约 2 周。是否按此推进。
5. **是否 OCR**：扫描版 PDF（如 C15）是否投入 OCR，还是直接排除。
